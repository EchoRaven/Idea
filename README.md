# Ideas 管理系统

位置：iCloud Drive / Ideas　（Mac、iPhone、iPad 自动同步）

## 核心思路

**捕获和评估分开。** 你的问题不是 idea 太多，是新 idea 一冒出来就抢走了
当前项目的注意力。所以：冒出来的瞬间只做"记下来"这一个动作，判断留到以后。

## 四个文件

| 文件 | 作用 | 什么时候碰它 |
|---|---|---|
| `INBOX.md` | 新 idea 的落地点 | 任何时候，30 秒记完就走 |
| `PROJECTS.md` | 在做的项目（≤3 个） | 开始/离开一个项目时 |
| `SOMEDAY.md` | 冷藏区 | 每周分流时、想开新项目前 |
| `archive/` | 完成或放弃的 | 项目结束时 |

## 终端命令

```
idea 做个自动整理书签的工具    # 一行记进 INBOX，不打断当前工作
inboxq                        # 看还有几条没分流
inbox / projects / someday    # 打开对应文件
```

## 两个必须养成的习惯

**1. 离开项目前写"断点"和"下一步"（60 秒）**
这是整套系统里最值钱的动作。"下一步"要具体到能立刻动手 ——
写"重构 auth 模块"没用，写"把 login.ts:42 的 token 校验拆成独立函数"才有用。

**2. 每周固定时间清 INBOX（15 分钟）**
每条只有四个去向：现在做（→ PROJECTS）、以后做（→ SOMEDAY）、
两分钟能做完（直接做掉）、删掉。**不允许留在 INBOX 里过夜第二周。**
INBOX 一旦堆积就会变成你不敢打开的地方，整套系统就死了。

## 服务器文档同步

各项目的文档散在不同的 GPU / 实验服务器上。`sync/pull-docs.sh` 用 rsync
把它们拉到本地，只取文档类文件，明确排除 checkpoint、数据集、日志。

```
sources            # 编辑来源配置：项目名 | ssh主机 | 远程路径 | 备注
pulldocs           # 拉取全部项目
pulldocs -n        # dry-run，先看会拉什么
pulldocs <项目名>   # 只拉一个项目
```

拉下来的文件落在 `projects/<项目名>/_inbox/`，新文件记录在 `sync/new-files.log`。

然后在 Claude Code 里说「**处理一下新文档**」，我会：

1. 逐份读完，写摘要，按类型归到 `progress/` 或 `tech/`，文件名统一加日期前缀
2. 和该项目历史文档对比 —— 指出反复延期的事项、前后矛盾的描述、没兑现的承诺
3. 技术方案文档给审阅意见 —— 设计漏洞、选型问题、和你其他项目重复造轮子的地方
4. 更新 `projects/<项目名>/_INDEX.md`，把要你注意的问题顶到最上面
5. 同步刷新 `PROJECTS.md` 里该项目的「断点」和「更新」日期

说「**这周的简报**」我会横向汇总所有项目，包含哪个项目多久没交文档了。

## 让 Claude 帮你维护

在 Claude Code 里直接说：

- 「记一个 idea：<内容>」
- 「我要开始做 X 项目了，给我看一下断点」
- 「我先去做别的了，帮我把 X 的断点和下一步写一下」
- 「帮我清一下 INBOX」—— 我会逐条问你去向并归位
- 「我这周做了什么」—— 我读 PROJECTS.md 的更新日期给你汇总
